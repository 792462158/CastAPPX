屏幕录制预览

- 点击右侧“屏幕录制”，在系统弹窗中选择共享整个屏幕或单个应用并确认，采集画面会实时显示在黑色预览区域。
- 左侧按钮仅按关闭 → 前置 → 后置 → 关闭循环切换，右侧按钮独立开启或停止屏幕录制，无需摄像头权限。录屏时摄像头关闭；点击左侧按钮切换到前置摄像头会先停止录屏。
- 点击“停止录屏”或通知栏中的停止操作结束采集；系统撤销共享时也会关闭预览。重新开始需要再次授权。
- 当前显示采集画面并传输可采集的设备内声音，不保存视频文件。共享整个屏幕并查看本应用时，预览会包含自身，产生递归画面。

构建验证：`./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug`。本次使用 Android
Studio 内置 JBR 完成验证。

Socket 画面接收

- 一台设备启动 Socket 服务器后会停止本地摄像头和录屏，禁用上方两个采集按钮，并进入“等待画面接收”。停止服务器后恢复按钮，画面保持关闭。
- 另一台设备通过局域网设备列表连接服务器，再开启/切换摄像头或屏幕录制，即可自动通过 UDP 发送画面。服务端在
  `preview_container` 中按原始比例显示，状态切为“正在接收画面”。连接前已开启的采集也会在连接后自动发送。
- TCP 保留文字聊天并协商画面会话；UDP 使用与服务端 TCP 相同的端口号。当前每次只接受一台设备。
- 画面为 MediaCodec 硬件 H.264 编码，目标码率 200 kbps（设备支持时启用 CBR 恒定码率）、最高约 15 帧/秒、最长边
  960 像素（尺寸向下对齐至 16 像素）。每个 UDP 分片最多 500 字节，每 8 个数据包额外发送一个 XOR
  修复包，可恢复每组丢失的一个数据包；保留最多 3 帧的重组窗口；普通帧期限为 500
  毫秒，关键帧按分片数量与发包间隔计算期限，上限为 2 秒。音频采集为 16 kHz 单声道 PCM16，发送前压缩为 32
  kbps AAC-LC，每个 1024 采样的音频帧独立发送，与画面复用接收 UDP 端口。视频与音频发送分别使用独立
  socket，避免发送锁竞争。
- 对端关闭采集时通过 TCP 显式通知接收端清空预览；TCP 断开时也立即清空。画面中断超过 2.5
  秒时保留最后一帧并显示等待恢复提示，恢复后自动继续。静止录屏画面会定期重发，以保留接收状态。
- 本次升级增加了 TCP 会话消息类型，两端均需安装新版。

Socket 声音传输与静音

- 摄像头画面发送时同时采集麦克风；需要录音权限。连接前开启摄像头时，连接成功后自动开始传音。断线、关闭摄像头、切换到录屏或离开前台时停止麦克风采集。
- 录屏使用同一次 MediaProjection 授权采集设备内音频，不混入麦克风。需要录音权限和 Android
  10+；旧系统仅发送画面并提示。停止录屏或系统撤销授权时释放音频采集。
- Android 仅允许采集同一用户下、允许被采集的媒体、游戏及 UNKNOWN
  用途音频。禁止采集的应用、通话等声音无法传输；此时可能只有画面或音频静音。这是系统限制，参见 [Android 官方说明](https://developer.android.com/media/platform/av-capture)。
- 接收端启动服务器后，预览区右下角显示“静音／取消静音”按钮，仅控制本应用接收音频的播放，不影响设备总音量、画面或文字聊天。选择在重连后保留。
- 接收端分别处理画面解码和音频播放，音频缓冲有界，过期/重复的音频包丢弃，丢包不重传。当前为实时尽力传输，未实现按时间戳严格音画同步；网络拥堵时可能出现断音。
- 两端建议均安装新版以使用音频功能。

画面稳定性

- 采集层统一限帧约 15 FPS，发送层不重复限帧；网络或设备较慢时自动跳过中间画面。
- 相机图像在复制像素后立即归还，编码和网络发送不再占用相机图像缓冲。当前采集接口仍会复制 Bitmap；GPU
  负责缩放和 RGB→YUV，硬件编码器输出 H.264。
- UDP 接收缓冲申请 2 MiB（实际大小由系统决定），解码队列只保留最新待处理帧，避免延迟堆积。
- H.264 每秒生成关键帧；关键帧附带 SPS/PPS。接收端检测到丢帧或解码队列溢出后，停止提交依赖帧并通过 TCP
  请求新关键帧（请求间隔至少 1000 毫秒），避免持续花屏；不等待旧视频数据重传。
- 接收端 MediaCodec 直接输出到 TextureView Surface，不再逐帧解码 JPEG 到 Bitmap；仅当具体解码器声明支持
  `FEATURE_LowLatency` 时请求低延迟模式；初始化失败时以普通模式重试，硬件解码器优先，再尝试其他可用解码器。
- 视频分片之间间隔约 12 毫秒，减少瞬时发包导致的 Wi-Fi 丢包。
- 编码队列只保留最新一帧，解码队列最多两帧，缓慢网络或设备不会无限积压旧画面。
- 目标设备需要硬件 H.264 编码器；初始化失败会提示重新连接，不静默退回高负载的软件编码。`AvcEncoder`
  输出编解码器信息，`AvcDecoder` 每 5 秒输出实际渲染帧数。
- TCP 只负责聊天、会话和关键帧请求；视频与音频均通过 UDP 传输。音频使用 AAC-LC，避免未压缩 PCM
  与视频争用链路带宽。
- 音视频 UDP 格式已经更新，两端必须同时更新。

诊断：发送端通过 TCP 每 5 秒报告累计编码帧数与视频包数；接收端 `SocketMedia` 日志记录收包和重组数，
`AvcDecoder` 日志记录输出帧数。硬件编码器兼容性错误会在连接状态中显示失败阶段及原因。

本次双机验证：摄像头持续传输超过 2 分钟，实测约 10
FPS，未再出现周期性整段零帧；已检查切换录屏、静音按钮、暂停发送进程后的断流提示与自动恢复、停止采集后回到等待状态。音频验证了
AAC 收发和解码链路，未进行人工听音或端到端音画延迟测量。

跨设备 H.264 解码兼容

- 配置接收端解码器前，从关键帧中提取 SPS/PPS，分别放入 `csd-0` / `csd-1`；提交画面数据时移除参数集，避免重复提交配置。
- 支持三字节、四字节 Annex B 起始码及四字节 AVCC 长度前缀，遇到截断或非法长度时拒绝解析。
- 低延迟能力以具体编解码器的声明为准，不能只依据 Android 版本强制开启；失败实例会释放，重试使用全新实例。

发送线程与关键帧恢复

- 硬件编码器输出交给独立的 UDP 发送线程，分片间隔不会阻塞编码器 drain 或相机输入。
- 已编码发送队列最多 4 帧；溢出时丢弃断裂的依赖链并等待新关键帧，不继续发送依赖被丢弃帧的 P 帧。
- 当前访问单元发送完成后再提出关键帧恢复请求，减少大关键帧发送期间重复请求造成的拥堵。诊断日志额外报告
  `droppedBeforeSend`，区分发送前主动丢弃与网络丢包。

Xiaomi / MediaTek 码率兼容

- 编码器选择优先考虑支持 CBR 或 CBR-FD 的硬件编码器，再考虑 VBR。
- Android 12+ 可能对 VBR 配置施加最低质量要求，将低码率请求提高。Xiaomi 2407FRK8EC 上实测 200000 bps
  的配置被系统提高到 1105920 bps。
- 读取编码器实际输出格式；若协商码率超过传输预算，在输出启动后使用公开 `PARAMETER_KEY_VIDEO_BITRATE`
  API 更新到目标码率，并记录结果。动态输出格式变更不会清空已有 SPS/PPS。
- 采集或接收界面在前台保持亮屏，关闭采集/接收后恢复，避免自动息屏中断预览和相机会话。
